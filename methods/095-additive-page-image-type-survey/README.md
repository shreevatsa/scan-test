# 095-additive-page-image-type-survey

A survey of up to twelve chosen PDF pages, sent as full page images, proposes **additions** to a book's current type list. It is the request recipe of [077](../077-gpt-6-1-terra-unit-types/README.md) and [078](../078-gemini-4-argon-high-unit-types/README.md) (PNG at 150 dpi capped at the scan's resolution, one caption `PDF page N` before each image, original detail on OpenAI and high resolution on Gemini, strict structured output, 16,384 output tokens, store false, the ordinary 75-second deadline) with one change: the request carries the book's current list (title, description, flows, every type with its region class, containment, flow and furniture role, relations, inline kinds and conventions; not its provenance or revision history) and asks only for

- `new_types`: types no existing type covers, each with a definition, a region class or `container` (with the existing types it may hold), where it belongs (`parents`, existing types that may contain it, and/or `flow`, an existing reading flow), a furniture flag, evidence pages and a short evidence text;
- `definition_edits`: optional clearer definitions of existing types, with a reason;
- `possible_duplicates`: groups of existing types that may be the same thing, as questions;
- `questions`: other uncertain distinctions.

Nothing in the response is applied. The response is checked against [response-schema.example.json](response-schema.example.json) (built for each book: the flow enum is the book's flows) and then against the current list: new names are lowercase snake_case, not in the list, its aliases or retired names, and not repeated; evidence pages are among the supplied pages; a container lists existing text types and a printed type none; parents are existing types that hold other units; furniture has no place in a flow; edits and duplicates name existing types. A response that fails is kept as a failed attempt with its charge. [prompt.example.txt](prompt.example.txt) shows the prompt for the draft types.

Models (one choice in the survey box, [config.json](config.json)): GPT-6.1 Terra, reasoning off (default), or Gemini 4 Argon, low thinking. The profile used is recorded in each call record and run record.

The app (Regions → Find unit types using a survey of pages) chooses this method when the page field names at most twelve pages, and [096](../096-additive-contact-sheet-type-survey/README.md) otherwise. Each attempt goes through the call ledger as `work/reader-calls/setup/type-survey-<uuid>.json` (image-free request, request hash, response, usage, time, estimated charge); an identical completed request is reused, and an identical one with an unresolved charge stops the survey unless a retry is allowed. Each run is `work/type-surveys/<run id>.json`; its proposals become pending items in `work/type-proposals/pending.json`, each with its source (method, run, model, pages), until a person adds (through the type-list `add` operation, plus `rules` for a second parent or a flow), dismisses (optionally as the same as an existing type) or answers it. The source is in [snapshot/](snapshot/) with [source hashes](source-sha256.json); 096 shares it.
